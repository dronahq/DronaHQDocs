UI Components

This guide explains how to build custom widgets using the UI component library provided by @openuidev/react-ui.

The package was previously named @crayonai/react-ui. Both names refer to the same project, but the rename introduced some breaking changes. When upgrading an older widget, review the Widgets FAQ for migration guidance.

Component index​

The following table lists the available components by category.

GroupComponents
LayoutCard, CardHeader, Separator
ActionsButton, Buttons, IconButton
TextTextContent, MarkDownRenderer, TextCallout, Callout, CodeBlock
TagsTag, TagBlock
ListsListBlock, ListItem, FollowUpBlock, FollowUpItem
StepsSteps, StepsItem
DisclosureAccordion, AccordionItem, AccordionTrigger, AccordionContent, Tabs, TabsList, TabsTrigger, TabsContent
MediaImage, ImageBlock, ImageGallery, Carousel, CarouselContent, CarouselItem, CarouselPrevious, CarouselNext
TableTable, ScrollableTable, TableHeader, TableBody, TableFooter, TableRow, TableHead, TableCell
Form inputsFormControl, Label, Hint, Input, TextArea, Select, SelectTrigger, SelectValue, SelectContent, SelectGroup, SelectLabel, SelectItem, SelectSeparator
ChoicesCheckBoxGroup, CheckBoxItem, RadioGroup, RadioItem, SwitchGroup, SwitchItem
RangeSlider, SliderBlock
DatesCalendar, DatePicker
ChartsLineChart, BarChart, AreaChart, ScrollableLineChart, ScrollableBarChart, ScrollableAreaChart, HorizontalBarChart, PieChart, RadialChart, SingleStackedBar, RadarChart, ScatterChart, MiniLineChart, MiniBarChart, MiniAreaChart

Shared prop vocabulary:

  • variant on containers (Card, Accordion, CheckBoxGroup, RadioGroup, SwitchGroup, TextContent, MarkDownRenderer): "card" (bordered surface), "sunk" (recessed fill) or "clear" (no chrome).
  • Status variant (Tag, TextCallout, Callout): "neutral" | "info" | "success" | "warning" | "danger".
  • Most components also accept className and style. CardHeader, Image, Input and Tag take styles instead.

Layout​

UI.Card — the standard surface. It accepts every <div> attribute.

PropTypeDefault
variant"card" \| "sunk" \| "clear""card"
width"standard" \| "full""standard"

UI.CardHeader — title row for a card.

PropTypeNotes
titlenode
subtitlenode
iconnodee.g. <Icons.User size={16} />
actionsButton / IconButton element or arrayright-aligned
stylesCSS objectnote: styles, not style

UI.Separator — horizontal rule (Radix Separator). Pass orientation="vertical" inside a flex row.

Example Code​

function ProfileCard(props) {
  const { name, role, bio } = props;
  return (
    <UI.Card variant="card" width="standard">
      <UI.CardHeader
        icon={<Icons.User size={16} />}
        title={name}
        subtitle={role}
        actions={<UI.IconButton icon={<Icons.MoreHorizontal size={14} />} variant="tertiary" size="small" aria-label="More" />}
      />
      <UI.Separator />
      <p style={{ margin: "12px 0 0", color: "var(--foreground, #111827)" }}>{bio}</p>
    </UI.Card>
  );
}
module.exports.default = ProfileCard;

Actions​

UI.Button — accepts every <button> attribute.

PropTypeDefault
variant"primary" \| "secondary" \| "tertiary""primary"
size"extra-small" \| "small" \| "medium" \| "large""medium"
buttonType"normal" \| "destructive""normal"
iconLeft / iconRightnode

UI.Buttons — lays out a group of Button/IconButton children. variant: "horizontal" (default) or "vertical".

UI.IconButton — square or round icon-only button. Give it an aria-label.

PropTypeDefault
iconnode (required)
variant"primary" \| "secondary" \| "tertiary""primary"
size"3-extra-small" \| "2-extra-small" \| "extra-small" \| "small" \| "medium" \| "large""medium"
shape"square" \| "circle""square"
appearance"normal" \| "destructive""normal"

Use the submit prop to send the user's choice back to the agent:

Example Code​

function ConfirmOrder(props) {
  const { orderId, submit } = props;
  const send = (message) => submit && submit({ title: "Order " + orderId, message: message });
  return (
    <UI.Card variant="card">
      <UI.CardHeader title={"Confirm order " + orderId + "?"} />
      <UI.Buttons variant="horizontal">
        <UI.Button variant="primary" iconLeft={<Icons.Check size={14} />} onClick={() => send("Confirm order " + orderId)}>
          Confirm
        </UI.Button>
        <UI.Button variant="secondary" onClick={() => send("Change order " + orderId)}>Change</UI.Button>
        <UI.Button variant="tertiary" buttonType="destructive" onClick={() => send("Cancel order " + orderId)}>
          Cancel
        </UI.Button>
      </UI.Buttons>
    </UI.Card>
  );
}
module.exports.default = ConfirmOrder;

Text​

UI.TextContent — a block of body text. variant: "clear" | "card" | "sunk".

UI.MarkDownRenderer — renders a markdown string.

PropTypeNotes
textMarkdownstring (required)
variant"clear" \| "card" \| "sunk"
optionsreact-markdown Optionsadvanced

The MarkdownText global is the app's own markdown renderer (the one chat uses). Use it when the text should match the surrounding chat messages.

UI.TextCallout / UI.Callout — highlighted message boxes. TextCallout is the compact inline form.

PropType
variant"neutral" \| "info" \| "success" \| "warning" \| "danger"
titlenode
descriptionnode

UI.CodeBlock — syntax-highlighted code.

PropType
languagestring (required), e.g. "json", "python"
codeStringstring (required)

Example Code​

function ReleaseNote(props) {
  const { version, summary, notes, snippet } = props;
  return (
    <UI.Card variant="card">

      <UI.Callout variant="success" title="No downtime" description="The rollout is incremental." />

function TicketTags(props) {

UI.FollowUpBlock / UI.FollowUpItem — suggested next questions. FollowUpItem takes text (required) and icon, plus button attributes such as onClick.

Example Code​

function TopArticles(props) {
  const { articles, suggestions, submit } = props;
  return (
    <UI.Card variant="card">
      <UI.CardHeader title="Top articles" />
      <UI.ListBlock variant="icon">
        {articles.map((a) => (
          <UI.ListItem
            key={a.title}
            title={a.title}
            subtitle={a.views + " views"}
            icon={<Icons.FileText size={14} />}
            actionIcon={<Icons.ChevronRight size={14} />}
            onClick={() => submit && submit({ message: "Open article: " + a.title })}
          />
        ))}
      </UI.ListBlock>
      <UI.FollowUpBlock>
        {suggestions.map((s) => (
          <UI.FollowUpItem key={s} text={s} onClick={() => submit && submit({ message: s })} />
        ))}
      </UI.FollowUpBlock>
    </UI.Card>
  );
}

Disclosure​

Accordion (Radix Accordion): UI.Accordion → UI.AccordionItem → UI.AccordionTrigger + UI.AccordionContent.

ComponentProps
Accordiontype: "single" | "multiple" (required); collapsible (single only); defaultValue; variant: "card" \| "sunk" \| "clear"
AccordionItemvalue (required, unique)
AccordionTriggertext (required), icon
AccordionContentchildren

Tabs (Radix Tabs): UI.Tabs → UI.TabsList with UI.TabsTriggers, then one UI.TabsContent per tab.

ComponentProps
TabsdefaultValue or value + onValueChange; variant: "clear" only
TabsListvariant: "title" | "iconTitle" | "iconTitleSubtext" | "imageTitle" | "imageTitleSubtext"
TabsTriggervalue and text (required); icon, subtext, image (URL)
TabsContentvalue (required)

Example Code​

function PlanDetails(props) {
  const { faqs, monthly, yearly } = props;
  return (
    <UI.Card variant="card">
      <UI.Tabs defaultValue="monthly">
        <UI.TabsList variant="iconTitle">
          <UI.TabsTrigger value="monthly" text="Monthly" icon={<Icons.Calendar size={14} />} />

          <UI.AccordionItem key={i} value={"faq-" + i}>
            <UI.AccordionTrigger text={f.q} icon={<Icons.HelpCircle size={14} />} />
            <UI.AccordionContent>{f.a}</UI.AccordionContent>
          </UI.AccordionItem>

Form inputs​

Widget inputs keep local state. Nothing reaches the agent until you call submit(...).

ComponentProps
FormControlgroups label + control + hint; hasError turns the hint red
Labelchildren (required), required, disabled, htmlFor
Hinthelper or error text; inherits hasError from FormControl
Inputevery <input> attribute; size: "small" \| "medium" \| "large"; hasError
TextAreaevery <textarea> attribute; rows; hasError
SelectRadix Select root: value / defaultValue, onValueChange; size: "sm" \| "md" \| "lg"
SelectTriggerwraps SelectValue; size, hideDropdownIcon
SelectValueplaceholder
SelectContentthe dropdown (portalled; it follows the theme automatically)
SelectGroup / SelectLabel / SelectSeparatorgrouping
SelectItemvalue (required), children, showTick

Example Code​

function CallbackForm(props) {
  const { topics, submit } = props;
  const [phone, setPhone] = useState("");
  const [topic, setTopic] = useState("");
  const [note, setNote] = useState("");
  const phoneError = phone.length > 0 && phone.replace(/\D/g, "").length < 10;
  const send = () =>
    submit && submit({ title: "Callback request", message: "Call me at " + phone + " about " + topic + ". " + note });
  return (
    <UI.Card variant="card">
      <UI.CardHeader title="Request a callback" />
      <UI.FormControl hasError={phoneError}>
        <UI.Label htmlFor="cb-phone" required>Phone</UI.Label>
        <UI.Input id="cb-phone" placeholder="+1 555 010 0000" value={phone} onChange={(e) => setPhone(e.target.value)} hasError={phoneError} />
        <UI.Hint>{phoneError ? "Enter at least 10 digits" : "We call within one business day"}</UI.Hint>
      </UI.FormControl>
      <UI.FormControl>
        <UI.Label>Topic</UI.Label>
        <UI.Select value={topic} onValueChange={setTopic}>
          <UI.SelectTrigger>
            <UI.SelectValue placeholder="Choose a topic" />
          </UI.SelectTrigger>
          <UI.SelectContent>
            <UI.SelectGroup>
              <UI.SelectLabel>Topics</UI.SelectLabel>
              {topics.map((t) => <UI.SelectItem key={t} value={t}>{t}</UI.SelectItem>)}
            </UI.SelectGroup>
          </UI.SelectContent>
        </UI.Select>
      </UI.FormControl>
      <UI.FormControl>
        <UI.Label>Notes</UI.Label>
        <UI.TextArea rows={3} value={note} onChange={(e) => setNote(e.target.value)} placeholder="Anything we should know?" />
      </UI.FormControl>
      <UI.Button disabled={!phone || phoneError || !topic} onClick={send}>Request callback</UI.Button>
    </UI.Card>
  );
}
module.exports.default = CallbackForm;

Example Data​

{ "topics": ["Billing", "Technical issue", "Sales"] }

Choices​

ComponentProps
CheckBoxGroupvariant: "card" \| "sunk" \| "clear"; children are CheckBoxItems
CheckBoxItemlabel, description, checked / defaultChecked, onChange(checked: boolean), name, value, disabled
RadioGroupRadix RadioGroup: value / defaultValue, onValueChange(value), variant
RadioItemvalue (required), label, description, disabled
SwitchGroupvariant; children are SwitchItems
SwitchItemlabel, description, checked / defaultChecked, onChange(checked: boolean), disabled

Note: CheckBoxItem and SwitchItem call onChange with a boolean, not a DOM event.

Example Code​

function NotificationPrefs(props) {
  const { channels, submit } = props;
  const [selected, setSelected] = useState([]);
  const [frequency, setFrequency] = useState("daily");
  const [muted, setMuted] = useState(false);
  const toggle = (c, on) => setSelected((prev) => (on ? prev.concat(c) : prev.filter((x) => x !== c)));
  const save = () =>
    submit && submit({ message: "Notify me via " + (selected.join(", ") || "nothing") + ", " + frequency + (muted ? ", muted on weekends" : "") });
  return (
    <UI.Card variant="card">
      <UI.CardHeader title="Notification preferences" />
      <UI.CheckBoxGroup variant="clear">
        {channels.map((c) => (
          <UI.CheckBoxItem key={c} label={c} checked={selected.includes(c)} onChange={(on) => toggle(c, on)} />
        ))}
      </UI.CheckBoxGroup>
      <UI.RadioGroup value={frequency} onValueChange={setFrequency} variant="clear">
        <UI.RadioItem value="instant" label="Instant" />
        <UI.RadioItem value="daily" label="Daily digest" description="One email at 9am" />
      </UI.RadioGroup>
      <UI.SwitchGroup variant="clear">
        <UI.SwitchItem label="Mute on weekends" checked={muted} onChange={setMuted} />
      </UI.SwitchGroup>
      <UI.Button onClick={save}>Save</UI.Button>
    </UI.Card>
  );
}
module.exports.default = NotificationPrefs;

Example Data​

{ "channels": ["Email", "SMS", "Slack"] }

Slider, SliderBlock​

UI.Slider — the bare track (Radix Slider). Values are always arrays: one number for a single thumb, two for a range.

PropTypeNotes
variant"continuous" \| "discrete" (required)discrete shows step dots
min, maxnumber (required)
stepnumber
value / defaultValuenumber[]
onValueChange / onValueCommit(value: number[]) => void

UI.SliderBlock — a labelled slider with editable number inputs. It takes the same props plus label (required) and manages its own value. Listen with onValueCommit.

Example Code​

function BudgetPicker(props) {

        label="Budget range ($)"
        variant="continuous"
        min={min}
        max={max}
        step={100}
        defaultValue={[min, max]}
        onValueCommit={(v) => submit && submit({ message: "Budget between $" + v[0] + " and $" + v[1] })}
      />
    </UI.Card>
  );
}

Dates​

UI.Calendar — an inline calendar built on react-day-picker v9. It takes all DayPicker props, most importantly:

PropNotes
mode"single" \| "multiple" \| "range"
selectedDate, Date[] or { from, to }, matching mode
onSelectcalled with the new selection
disabledmatcher, e.g. { before: new Date() }

Props arrive as JSON, so dates are strings. Convert them with new Date(str) before passing them in.

UI.DatePicker — a calendar with a dropdown header, single or range.

PropType
mode"single" \| "range"
selectedSingleDate / setSelectedSingleDateDate and its setter (single mode)
selectedRangeDates / setSelectedRangeDates{ from, to } and its setter (range mode)

Example Code​

function BookingDates(props) {
  const { busyDays, submit } = props;
  const [day, setDay] = useState();
  const [range, setRange] = useState();
  const busy = (busyDays || []).map((d) => new Date(d));
  return (
    <UI.Card variant="card">
      <UI.CardHeader title="Pick a day" subtitle="Highlighted days are fully booked" />
      <UI.Calendar mode="multiple" selected={busy} />
      <UI.DatePicker mode="single" selectedSingleDate={day} setSelectedSingleDate={setDay} />
      <UI.DatePicker mode="range" selectedRangeDates={range} setSelectedRangeDates={setRange} />
      <UI.Button
        disabled={!day}
        onClick={() => submit && submit({ message: "Book " + day.toDateString() })}
      >
        Book
      </UI.Button>
    </UI.Card>
  );
}
module.exports.default = BookingDates;

Charts​

Charts use a flat rows data contract. It is not Chart.js: there is no labels, datasets or options, and those props are silently ignored, so you get empty axes.

Which chart​

ComponentUse forData contract
LineChart, BarChart, AreaCharttrends and comparisons over categories; they fit the container widthrows + categoryKey
ScrollableLineChart, ScrollableBarChart, ScrollableAreaChartlong series (dozens of points); they scroll horizontally instead of squeezingrows + categoryKey
HorizontalBarChartranked lists with long labelsrows + categoryKey
PieChartpart-to-whole (variant="donut" for a donut)rows + categoryKey + dataKey
RadialChartpart-to-whole as rings or a gaugerows + categoryKey + dataKey
SingleStackedBarpart-to-whole as one horizontal barrows + categoryKey + dataKey
RadarChartcomparing several metrics per categoryrows + categoryKey
ScatterChartcorrelation between two numeric valuesdatasets of {x, y} points
MiniLineChart, MiniBarChart, MiniAreaChartsparklines inside KPI tilesnumber[] or [{ value, label? }]

There is no DonutChart, Histogram or PieChartCondensed.

2D charts​

  • data is a flat array of row objects, one per x-axis point: [{ month: "Jan", sales: 100, profit: 40 }, ...].
  • categoryKey names the x-axis field, and every row must contain it.
  • Every other numeric key is a series. Two series means two numeric keys per row, not two arrays. The legend shows the key name.
  • Always pass height (e.g. height={240}), otherwise the chart can collapse to zero height.

How customPalette is applied​

The palette is not read in order. Every chart picks the colours for n series outward from the middle of the array:

SeriesColours used from a palette p of length L (mid = floor(L / 2))
1p[mid]
2p[mid - 1], p[mid + 1]
3 or moren consecutive colours centred on mid, wrapping around the ends

In practice:

  • 1 series: customPalette={["#3b82f6"]}.
  • 2 series: put a spacer in the middle: customPalette={[first, "#CBD5E1", second]}. A two-colour palette makes the second series black, because p[2] doesn't exist.
  • 3 series: three colours, in order.
  • 4 or more: pass exactly n colours and accept that the order rotates, or leave customPalette out and use theme ("ocean", "orchid", "emerald", "spectrum", "sunset", "vivid").

The same rule applies to PieChart, RadialChart and SingleStackedBar (one colour per slice). The mini charts take a single lineColor / barColor / areaColor instead.

RadarChart and ScatterChart​

UI.RadarChart — rows + categoryKey, where each other numeric key is a series. variant: "line" | "area", plus areaOpacity, strokeWidth, grid and legend.

UI.ScatterChart — data is a list of datasets: [{ name, data: [{ x, y, z? }] }]. Other props: xAxisDataKey / yAxisDataKey (default "x" / "y"), shape ("circle" | "square"), xAxisLabel, yAxisLabel, grid, legend and height.

Sparklines with no axes. data is number[] or [{ value, label? }]. Use size (a number or CSS size) for the height, and lineColor / barColor / areaColor for a single colour. MiniAreaChart also takes useGradient and opacity.

Example Code​

function KpiTiles(props) {
  const { kpis } = props;
  const tile = { flex: 1, minWidth: 140, padding: 12, border: "1px solid var(--border, #e5e7eb)", borderRadius: 10 };
  return (
    <div style={{ display: "flex", gap: 12, flexWrap: "wrap" }}>
      {kpis.map((k) => (
        <div key={k.label} style={tile}>
          <div style={{ fontSize: 12, opacity: 0.7 }}>{k.label}</div>
          <div style={{ fontSize: 20, fontWeight: 700 }}>{k.value}</div>
          {k.kind === "bar" ? <UI.MiniBarChart data={k.trend} size={40} barColor="#6366F1" />
            : k.kind === "area" ? <UI.MiniAreaChart data={k.trend} size={40} areaColor="#14B8A6" useGradient />
            : <UI.MiniLineChart data={k.trend} size={40} lineColor="#EC4899" />}
        </div>
      ))}
    </div>
  );
}
module.exports.default = KpiTiles;
