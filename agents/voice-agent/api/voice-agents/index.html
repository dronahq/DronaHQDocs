Voice Agents API

The Voice Agents API creates, reads, updates and deletes voice agents from your own system. Send instructions and tools, and everything else takes the platform defaults, the same ones New agent uses in the builder. To change an agent later, send only the part that changes: one tool, one parameter or one setting.

When to Use This​

  • Create an agent for each of your customers from your own product.
  • Keep an agent's instructions and tools in sync with your system.
  • Set the values its {{variable.NAME}} placeholders fill in, such as a store name or an API key.
  • Copy a tool from one agent to another.
  • Delete agents you no longer need.

Prerequisites​

  • An API Key with the Voice agents scope, or the older Agent Creator scope.
  • The Voice agents scope gives no access to calls, dispatch or campaigns, and the Calls and Campaigns scopes give no access to this API. A key that builds agents and also calls them needs both, for example Voice agents and Calls.
  • The key's Agent Access sets which agents it can read, change and delete:
    • All Agents: every voice agent in the workspace.
    • Specific agents: only the agents on the list. List agents leaves the others out, and a request for one of them fails with 403. An agent the key creates is added to its list, so the key can keep managing what it builds.

Authentication​

Every request must include your key, in the api-key header or as a Bearer token. See API Keys for how to create one. The examples on this page use api-key.

api-key: sk_<your-secret>

or

Authorization: Bearer sk_<your-secret>

Every request made with one of your keys is recorded in Request Logs, including the failures.

Base path

These endpoints are served at the root of your DronaHQ host: https://<your-dronahq-host>/voice/agents. There is no /api/v1 prefix.

Responses contain your secrets

An agent is returned as stored, including the secrets you put in it, such as a fixed x-api-key header on a tool. The exceptions: webhook auth tokens come back as <redacted>, and variables masked. Call this API from your backend, and don't log full responses.

Draft and published​

Like the builder, create and update change the agent's draft, and Get an agent reads it: its instructions, tools and config are the draft's.

Where the agent runsUses
The builder's playground and test callsThe draft, so changes show at once
Inbound numbers, dispatch, campaigns and shared web widgetsThe published version

So while the draft has changes that aren't published yet, what Get an agent returns is not what inbound calls, dispatch and campaigns run. Publish to make them the same.

A new agent has no published version. Dispatch and campaigns refuse it until it is published, unless dispatch sends "agent_version": "draft".

To publish, send "publish": true on create or update, or click Publish in the builder. Each publish saves a new minor version. The publish field of the response says what happened:

publishMeaning
nullYou didn't ask to publish
{"published": true, "version": "0.1.0", "version_uuid": "…", "release_type": "minor", "release_notes": "…"}Published
{"published": false, "error": "…"}The publish failed. Your changes were saved to the draft first, so they are kept. Retry with {"publish": true}. An unexpected failure reads "Publish failed; the draft was saved."

Get one part with query​

Add ?query= to get one piece of the agent instead of the whole document. The path is read against the agent object above.

curl -G https://<your-dronahq-host>/voice/agents/3b7e1c2a-5d4f-4e8a-9b6c-0f1e2d3c4b5a \
  -H "api-key: sk_your-generated-secret-here" \
  --data-urlencode "query=tools[name=get_order_status].metadata.url"
{
  "status": "success",
  "agent_uuid": "3b7e1c2a-5d4f-4e8a-9b6c-0f1e2d3c4b5a",
  "query": "tools[name=get_order_status].metadata.url",
  "result": "https://api.example.com/orders/{{order_number}}"
}

result is exactly what the path points to: an object, an array, a string, a number, a boolean or null.

WriteTo getExample
key.keyA field inside an objectconfig.llm.model
[n] or .nThe item at position n, from 0. A negative n counts from the endtools[0], tools.0, tools[-1]
[field=value]The first item whose field equals value, compared as texttools[id=f4513ecc-…], tools[active=true]
[field="value"]The same, for a value with spaces or ] in ittools[name="order status"]
["key"]A field whose name has ., [ or ] in itproperties["a.b"]
[*]Every item. The rest of the path applies to each, and the result is a listtools[*].name
  • After [*], items that lack the rest of the path are skipped. tools[*].metadata.url lists the URLs of the tools that have one.
  • Without [*], a step that matches nothing is a 404 that names the step in detail.at. A typo never comes back as null.
  • A path can be up to 500 characters and 32 steps. URL-encode it: curl -G --data-urlencode does it for you.
HTTP statusCause
400The path is empty, malformed, or longer than 32 steps. detail.message says what is wrong
404The path matched nothing. detail.at names the step that failed
422query is longer than 500 characters

Create an agent​

POST /voice/agents

Every field is optional. What you leave out takes the platform default.

Body​

FieldTypeRequiredDescription
namestringNoDisplay name, up to 128 characters. Left out or empty: New_Voice_Agent
descriptionstringNoShown in the agent list. Default ""
instructionsstringNoThe system prompt. Default: the platform's prompt. If you also send config.llm.system_instructions, instructions wins

Tools​

A tool lets the agent call your API during a conversation. The agent reads the tool's description to decide when to call it, and each parameter's description to decide what to send.

A tool entry takes one of two forms:

  • The HTTP form, without tool_type: the flat fields below. Use it to create and edit HTTP tools.
  • The raw form, with tool_type: a tool exactly as Get an agent returns it. Use it to copy a tool, or for tool types the HTTP form doesn't cover. See Raw tool entries.

Raw tool entries​

An entry with a tool_type is stored as you send it.

  • tool_type must be a type the platform supports. The error for an unknown one lists them.
  • A missing id, key or active, and the default voice settings, are filled in. Apart from the name rules, nothing else is checked.
  • On update, a raw entry is matched like any other: by id if it has one, otherwise by name. A match is deep-merged onto the stored tool. With no match, the tool is added, and an id this agent doesn't have is kept.
  • To change a tool that isn't an HTTP tool, use the raw form. The HTTP form refuses it with 422.
  • Keep a tool's key as it is: for some tool types it selects what the tool does. When a raw entry renames a tool, send the tool's current key with it, or the key is rebuilt from the new name.

Update an agent​

PATCH /voice/agents/{agent_uuid}

Changes only what you send. A field you leave out stays as it is.

Body​

FieldTypeDescription
namestringReplaced. 1 to 128 characters: "" is a 422, and a name of only spaces is ignored
descriptionstringReplaced
instructionsstringReplaced. If you also send config.llm.system_instructions, instructions wins
toolsarrayEach entry updates its matching tool, or is added. See below
remove_toolsarray of stringsTools to delete, by name or id
configobjectDeep-merged onto the current settings. See Config
variablesobjectEach name is set to its value, and null deletes it. Variables you leave out are kept. See Variables
add_knowledge_basesarray of stringsKnowledge bases to attach, by name, keeping the others. See Attach or detach one
remove_knowledge_basesarray of stringsKnowledge bases to detach, by name
add_structured_outputsarray of stringsStructured output ids to link, keeping the others

An unknown top-level field is rejected with 422. Every update, even an empty one, sets updated_at and updated_by.

Attach or detach one knowledge base or structured output​

Sending config.knowledge_base.consumed or config.structured_outputs_json replaces the whole list. To change one entry, use the add and remove fields:

{
  "add_knowledge_bases": ["pricing_faq"],
  "remove_structured_outputs": ["SO-12"]
}
  • Removes run first. Removing one the agent doesn't have is a 422. Adding one it already has changes nothing.
  • A knowledge base is added by its name from the Knowledge Bases API, with the settings the builder gives a newly attached one: its embedding model, the default lookup sound and message, and the agent's "run in background" setting. All of an agent's knowledge bases must use the same embedding model. A mix, or a name your workspace doesn't have, is a 422.
  • A structured output is added by id: one of your workspace's (SO-…) or a library entry (LSO-…). It goes at the end of the list.
  • A key limited to some agents can't attach a knowledge base or link an output that only other agents use.
  • Don't send both forms for one list in the same request: that is a 422.

If you send the whole consumed list yourself, give each entry its default_embedding_model (the embedding_model the Knowledge Bases API returns). Without it, every knowledge base search on the agent fails.

How tool changes are applied​

  1. remove_tools runs first. Each value is a tool's exact name or its id. One that matches no tool is a 422. So one request can remove a tool and add a new one with the same name.
  2. Each tools entry is then matched to a tool on the agent: by id when it has one, otherwise by name. Names match exactly, so Get_Order_Status doesn't match get_order_status.
  3. A match is updated.
    • The fields you send replace the old ones. The fields you leave out keep their values.
    • parameters merge by parameter name. A parameter you name keeps every field you don't send, and a new name is added. Sending a value without agent_decides makes the parameter fixed.
    • required: false takes a parameter out of the required list. remove_parameters deletes parameters.
    • static_body merges by key. A key set to null is removed.
  4. No match: the tool is added. A new HTTP tool needs description and url. An HTTP-form entry whose id isn't on the agent is a 422 (no tool with id). A raw entry with that id is added instead.
  5. name is required on every HTTP-form entry, even one matched by id. If it differs from the tool's current name, the tool is renamed. new_name also renames.
  6. All or nothing. If any entry is invalid, or two tools would share a name (ignoring case), nothing is saved.

"tools": [] changes nothing: it doesn't remove your tools. Use remove_tools for that.

If the change would take the agent over your plan's tool limit, the request fails with 403 and detail.upgrade_required: true. The limit is checked only when the number of tools grows.

Example: add a tool​

An entry whose name the agent doesn't have yet is created:

curl -X PATCH https://<your-dronahq-host>/voice/agents/3b7e1c2a-5d4f-4e8a-9b6c-0f1e2d3c4b5a \
  -H "api-key: sk_your-generated-secret-here" \
  -H "Content-Type: application/json" \
  -d '{
    "tools": [
      {
        "name": "cancel_order",
        "description": "Cancel an order the caller asks to cancel. Call it only after the caller confirms.",
        "method": "POST",
        "url": "https://api.example.com/orders/{{order_number}}/cancel",
        "parameters": [
          { "name": "order_number", "in": "path", "required": true, "description": "The order number to cancel." },
          { "name": "x-api-key", "in": "header", "value": "<your-api-key>" }
        ]
      }
    ]
  }'

Example: change one parameter​

Only the x-api-key value changes. The rest of the tool stays as it is:

{ "tools": [ { "name": "get_order_status", "parameters": [ { "name": "x-api-key", "value": "<your-new-api-key>" } ] } ] }

Example: remove a tool​

curl -X PATCH https://<your-dronahq-host>/voice/agents/3b7e1c2a-5d4f-4e8a-9b6c-0f1e2d3c4b5a \
  -H "api-key: sk_your-generated-secret-here" \
  -H "Content-Type: application/json" \
  -d '{ "remove_tools": ["cancel_order"] }'

Copy a tool from another agent​

Read the tool from the source agent, then send the result unchanged in tools on the target agent:

curl -G https://<your-dronahq-host>/voice/agents/<source-agent-uuid> \
  -H "api-key: sk_your-generated-secret-here" \
  --data-urlencode "query=tools[name=get_order_status]"

curl -X PATCH https://<your-dronahq-host>/voice/agents/<target-agent-uuid> \
  -H "api-key: sk_your-generated-secret-here" \
  -H "Content-Type: application/json" \
  -d '{ "tools": [ <the result object from the first request> ] }'
  • The copy keeps the tool's id, as duplicating an agent in the builder does.
  • If the target already has a tool with that id, for example because it was duplicated from the source, that tool is updated instead.
  • If the target already has a tool with the same name, the request fails with 422. Rename the copy by changing its name before you send it.
  • Agent variables the tool uses ({{variable.NAME}}) belong to each agent. Create them on the target agent too.

Response — 200 OK​

{
  "status": "success",
  "agent": { "…": "the whole agent, as in Get an agent" },
  "changed": ["tools"],
  "tools": { "added": ["cancel_order"], "updated": [], "removed": [] },
  "variables": { "added": [], "updated": [], "removed": [] },
  "publish": null
}

changed lists what the update actually changed: name, description, instructions, config.<section>, tools, variables. A value the agent already had doesn't count, so [] means nothing changed. With ?response=summary, agent is the short one and publish_state is added (see A short response).

Variables​

An agent's variables are the values {{variable.NAME}} fills in. They work in:

  • the instructions;
  • the greeting (runtime_behaviour.firstMessage);
  • tool URLs and fixed parameter values;
  • the pre-call and post-call webhooks.

A variable gives a placeholder its default value. Dispatch can override it for the calls it places with dynamic_variables, and a campaign can map a CSV column to it. A placeholder whose variable doesn't exist is left as written.

  • Names start with a letter or underscore and hold only letters, digits and underscores, up to 200 characters: customer_name, amount_due. Any other name is a 422.
  • Values are strings. They are stored encrypted. Every read returns them masked: the first two and last two characters (As***ma), or **** for four characters or fewer. No request returns a value in full.
Publish after you change a variable

Variables belong to the draft, like every other change. Live calls use the variables of the published version. Dispatch's dynamic_variables may only name variables of the version it calls; other names are dropped and listed in ignored_variables. The builder's unpublished-changes marker doesn't track variables, so a variable-only change doesn't show there.

With the rest of the agent​

Send variables on create or update. On an update, each name you send is set, null deletes one, and the variables you leave out are kept. They are saved with the rest of the request, so "publish": true publishes them too.

curl -X PATCH https://<your-dronahq-host>/voice/agents/3b7e1c2a-5d4f-4e8a-9b6c-0f1e2d3c4b5a \
  -H "api-key: sk_your-generated-secret-here" \
  -H "Content-Type: application/json" \
  -d '{
    "instructions": "You call {{variable.customer_name}} about an unpaid bill of {{variable.amount_due}}.",
    "variables": { "customer_name": "there", "amount_due": "your balance", "old_promo": null },
    "publish": true
  }'

The response's variables says what changed: {"added": [...], "updated": [...], "removed": [...]}. Setting a variable to the value it already has, or deleting one that doesn't exist, changes nothing and isn't listed.

Config​

config holds every setting other than the name, description, instructions, tools and variables. It has the same sections as agent.config in Get an agent, and it is deep-merged onto what the agent already has:

  • An object merges key by key, at every depth. Send only the keys you change.
  • Anything else, including an array, replaces the old value at that path. Send the whole list.
{ "config": { "llm": { "temperature": 0.4 } } }

This changes the temperature and leaves every other setting as it was.

Delete an agent​

DELETE /voice/agents/{agent_uuid}

Deletes a voice agent permanently, as Delete does in the builder. Its draft and published versions, version history, tools, variables, share link and agent memories are deleted, and nothing can restore them.

curl -X DELETE https://<your-dronahq-host>/voice/agents/3b7e1c2a-5d4f-4e8a-9b6c-0f1e2d3c4b5a \
  -H "api-key: sk_your-generated-secret-here"

Response — 200 OK​

{
  "status": "success",
  "agent_uuid": "3b7e1c2a-5d4f-4e8a-9b6c-0f1e2d3c4b5a",
  "unlinked_numbers": ["+14155550100"],
  "disabled_keys": 0,
  "this_key_disabled": false
}
FieldDescription
unlinked_numbersPhone numbers that stopped answering for this agent. Numbers are unlinked, never deleted. A number left with no agent goes back to your pool
disabled_keysAPI keys this request disabled. See below
this_key_disabledtrue when one of them is the key you sent the request with
  • API keys. The agent is removed from every key's Agent Access list. A key whose list ends up empty can't reach any agent, so it is disabled.   • Call logs, recordings and finished campaigns are kept as history.

When the delete is refused​

Each of these refusals happens before anything is deleted, so the agent stays as it was.

Calls in progress: 409. A call is running on the agent: an inbound or outbound phone call (including one still ringing), a web call or a test simulation. detail.live_calls lists them, with direction set to inbound, outbound, web or simulation. call_id can be null. Try again once they have ended.

{
  "detail": {
    "status": "error",
    "message": "This agent has 1 call(s) in progress. Try again once they have ended.",
    "live_calls": [ { "call_id": "0d9c41e2a6f84b7c9e3f5a1b2c4d6e8f", "direction": "inbound" } ]
  }
}

Calls can't be checked: 503. DronaHQ couldn't check for calls in progress. Retry.

Campaigns: 409. A campaign that uses the agent is scheduled, queued, running or paused. detail.blocking lists each one with the action that clears it: stop a campaign that has started, or reconfigure a scheduled one to use another agent.

{
  "detail": {
    "status": "error",
    "message": "This agent is used by 1 campaign(s) that must be dealt with first.",
    "blocking": [
      {
        "campaign_uuid": "cccccccc-1111-2222-3333-444444444444",
        "campaign_name": "Renewal reminders",
        "status": "running",
        "required_action": "stop"
      }
    ]
  }
}

A second delete of the same agent returns 404.

Errors​

Error shapes​

Every error has a detail field, but its shape depends on the error:

detail isWhen
A string, for example "Voice agent not found."401 and 403 from the key or its Agent Access, and 404 for an agent
An object with a messageA bad tool (detail.tool names it), a bad config section or a provider calls can't run (422), a query error (400 or 404, with query and at), the plan's tool limit (403, with upgrade_required), a refused delete (409 or 503), and 500
An array of errorsA body or parameter that fails validation (422): an unknown top-level field, a wrong type, a name over 128 characters, or a query over 500 characters
{ "detail": { "message": "no tool with id 'f4513ecc-50e6-41c5-8961-27e5ece2824c'", "tool": "get_order_status" } }
{ "detail": [ { "type": "extra_forbidden", "loc": ["body", "instruction"], "msg": "Extra inputs are not permitted", "input": "…" } ] }

Body validation errors are 422, never 400.

Status codes​

HTTP statusCauseFix
400A malformed query pathFix the path; detail.message says what is wrong
401The key is missing, unknown, disabled or expiredCheck the key under Developer → API Keys: it must be enabled and not expired
403The key lacks the Voice agents scope, or the agent isn't on its Agent Access listFix the key's scopes or Agent Access
403The change would exceed your plan's tool limit (detail.upgrade_required: true)Remove tools, or upgrade
404No voice agent with this id in the key's workspace, or a query path that matched nothingCheck the id with List agents. An agent in another workspace is a 404 too
409Delete only: a call or a campaign is in progress on the agentSee When the delete is refused
422The body is invalid: an unknown field, a bad tool or parameter, a config section that isn't allowed, or a provider calls can't run. On the model and voice lists: a provider calls can't run, or an unknown regionRead detail
500Unexpected server error. Nothing was saved or deletedRetry; contact support if it persists
503Delete only: calls in progress couldn't be checked. Nothing was deletedRetry
